# Python 虚拟环境练习回答

本文记录[虚拟环境](../virtual-environments.md)课程“练习与验收”中的书面回答。环境创建、脚本运行和编辑器配置等实操已经完成，不在此重复记录。

## 为什么不建议使用管理员权限向系统 Python 安装项目依赖？

系统 Python 可能被操作系统或其他工具共同使用。以管理员权限直接安装或升级包，可能覆盖共享版本、破坏其他项目，甚至影响依赖系统 Python 的工具。这些改动也难以在其他电脑上准确复现。把依赖安装在项目独立的虚拟环境中，可以限制影响范围，并通过项目配置重新搭建环境。

## 激活虚拟环境实际修改了什么？

激活脚本主要临时修改当前终端的 `PATH`，让虚拟环境中的 `python` 和其他命令排在系统命令之前；它通常还会设置 `VIRTUAL_ENV` 并调整命令提示符。激活不会创建环境，也不会修改 Python 源码。关闭终端或执行 `deactivate` 后，这些终端环境变量的修改就会失效。

## 为什么 `.venv/` 不应提交，而锁文件通常应提交？

`.venv/` 是可以重新生成的本地产物，体积较大，并且包含操作系统、Python 安装位置和本机绝对路径等机器相关内容。锁文件体积较小，记录依赖解析得到的准确版本，用于在其他电脑或持续集成环境中重建一致的依赖集合。因此通常忽略 `.venv/`，但提交项目采用的锁文件。

## `uv run` 为什么可以在不激活环境的情况下工作？

激活只是让 shell 通过 `PATH` 找到虚拟环境中的命令。`uv run` 不依赖当前 shell 的 `PATH` 切换，而是根据当前项目的 `pyproject.toml`、锁文件和环境配置找到或准备项目环境，再直接使用其中的解释器运行命令。因此它不要求用户先手动执行激活脚本。
