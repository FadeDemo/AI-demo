# RAG 实战

第二阶段已经能从问题出发找回文档。本专题继续往下做，让程序把有用的片段交给模型，返回能够查证的回答。资料更新后，旧内容应退出当前查询；用户权限不同，能看到的资料也应不同。

这是 [Roadmap 第三阶段](../../roadmap.md#6-第-3-阶段-rag-实战主线约-7-周)的配套课程。七课对应路线中的七项实战内容，每课可以分多次完成。完成后应得到一个带引用、可评测、能在本机部署的中文技术文档知识库。

## 学习前提

- 完成 [LLM 使用基础](../../llm/index.md)，能够调用模型、控制输入预算、验证结构化输出，并区分可重试失败与永久失败。
- 完成 [RAG 检索基础](../foundations/index.md)，已有文档读取、关键词和向量检索，以及固定 20 个问题的评测入口。
- 能运行离线测试，理解 HTTP 请求、JSON 和环境变量。需要回看时使用 [Python 基础](../../python/index.md)与[工程基础](../../engineering/index.md)。

代码继续放在 [RAG Knowledge Base](../../../projects/rag-knowledge-base/README.md) 配套项目中。复用已有的模型适配能力，按课程新增行为逐步接入。课程约定数据含义和外部行为，具体类名、文件拆分及依赖注入方式由实现决定。

## 两条处理流程

摄取是把原始资料转换成可检索记录的过程。查询使用已经准备好的记录，一次提问不应重新读取并编码全部资料。

```text
摄取流程
读取资料 → 清理并保留来源 → 切块 → 编码 → 保存可查询的资料版本

查询流程
接收问题 → 确定可见资料 → 检索 → 可选重排 → 选择证据
→ 组织模型输入 → 生成候选回答 → 验证结构与引用 → 返回结果
```

第一课只做片段检索，第二课接入生成。第三课建立更新与版本约定，第四课把存储交给数据库并实现检索范围过滤。后面各课在这些能力之上继续增加行为。

## 怎么使用例子

[配套教学材料](practice-materials.md)提供完整的虚构资料、问题和故障情形，用于手算与小规模测试。它们不描述真实产品，不替代第二阶段的真实语料和 Embedding 实验。

每课先解释一次可追踪的处理过程，再给局部例子和实现任务。先在纸上预测结果，再运行自己的程序比较。出现差异时，先核对输入、版本和计算口径。

默认测试使用模型、时钟和外部存储的测试替身，不联网、不下载模型、不需要密钥。真实模型、数据库和容器检查单独显式运行。替身能证明应用如何处理约定输入；真实实验才用于判断模型效果、数据库适配与部署情况。

课程不预先创建个人回答文件。任务说明与通过条件都在课程正文中，实际学习时再按需记录回答、实验报告和验收结论。

## 各课的边界

前两课先使用公开教学资料和本机入口。第三课用单进程、串行摄取完成版本发布，暂不要求分布式事务。第四课提供固定测试身份的资料范围，第七课才接入可信身份认证。第六课中权限测试使用第四课已有的范围过滤，不能提前把身份认证列为通过条件。

第二课选择完整响应后再验证和展示，便于先把引用契约做清楚。已有终端助手的流式能力可以保留，本专题不要求重新实现流式输出。跨用户在线服务、高可用集群和完整 OCR 系统也不属于这七课的必需产物。

## 综合验收

完成七课的任务后，按下面顺序整理证据。

1. 用同一应用入口演示摄取、片段检索、带引用回答和资料不足时的处理，引用能回到实际送入模型的原文。
2. 更新并删除一份资料，证明后续查询使用正确版本。数据库重启后仍能恢复当前资料。
3. 用固定材料比较向量、BM25 和混合检索，再记录重排及问题改写的效果。保留没有改善的结果。
4. 提交 50～100 条固定问题的评测材料和逐题报告，分别列出检索、生成、引用、延迟、用量及失败记录。
5. 从 HTTP 入口验证越权资料无法进入候选、重排、模型输入或缓存响应，注入文字无法改变应用权限。
6. 完成默认离线测试及项目规定的格式与 lint 检查，另外提供真实模型、数据库和 Compose 验证记录。
7. README 写明准备、运行、测试和复现命令，附一张说明摄取与查询的数据流图，以及 3～5 分钟演示。

验收只按对应课程已经说明的契约进行。代码已运行、文档已写完和学习完成分别记录；学习状态由实际学习进度决定。
