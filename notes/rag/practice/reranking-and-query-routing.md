# 重排、问题改写与路由

“那认证失败呢”可能是一个完整对话里的好问题，单独检索时却缺少对象。另一些问题已经找到了正确资料，只是它排在候选列表后面。本课分别处理问题表达和候选顺序，并为不适合查询知识库的请求确定去向。

完成后，应用能连续处理多轮输入，保存明确的历史，把需要补充指代的问题改写成独立问题，再执行可开关的多查询和重排流程。

## 学习前提与本课范围

第四课提供可见资料范围内的检索，第二课提供回答验证。本课不让模型选择任意工具，只执行应用预先安排的处理步骤。用户身份与允许组始终来自第四课的身份上下文，任何改写结果都不能更改它。

前面几个任务的单次 HTTP 调用尚未提供多轮会话。本课任务 2 会明确建立历史保存和连续调用入口，不能仅在测试中手工拼一份历史就宣称会话已经接通。

## 1. 重排只能重新查看已有候选

初检先找回 C 个候选，重排再根据问题与每个候选的关系给分，选出最终 K 个。这里 C 必须不小于 K，例如先取 20 再选 5；可见候选不足时使用实际数量。

交叉编码器是把问题和片段共同输入模型进行评分的方法，英文为 Cross-Encoder。它与分别编码问题和文档的向量检索不同，需要对每个候选重新计算。应用先限制候选数量，再调用重排模型。方法与示例见 [Sentence Transformers 检索与重排文档](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。

重排模型的分数范围依模型与输出设置而异，本课只比较同一次重排内部的分数，不把它当作回答正确的概率。

假设某题相关片段为 B、E，初检返回 `[A, C, B, D]`。重排改为 `[B, A, C, D]`，前两位现在含有 B，但 E 仍未出现。初检候选的 Recall@4 保持 1/2，最终 Recall@2 从 0 变成 1/2，RR@2 从 0 变成 1。

保留初检分数、初检名次、重排分数和最终名次，避免覆盖后无法解释差异。本课比较 Recall 与 MRR 即可，分级相关性的 NDCG 在第六课引入。

## 2. 先让应用真正拥有对话历史

会话是一段连续输入及应用结果的记录。本课用应用生成的会话编号标识它，保存已接受的用户消息和对应回答状态。每次处理先记录用户输入，完成后记录成功、依据不足或技术失败，失败记录保留类别并剔除异常正文。

同一会话与创建它的身份上下文绑定。通过第四课固定游客身份创建的会话，不能在后续请求中切换成工作人员。历史存储先用内存，关闭应用后可以丢失，不要求提前实现长期记忆。

为问题改写选择历史时，使用最近两轮成功或依据不足的对话，加上当前问题。两轮只是本课的有限窗口选择；若超出输入预算，按整轮从旧到新移除并记录原因。失败异常和未经验证的模型文本不进入改写输入。

| 连续输入                                   | 独立检索问题示例                   |
| ------------------------------------------ | ---------------------------------- |
| 第一轮问“星桥的只读查询超时后最多重试几次” | 使用原问题                         |
| 第二轮问“那认证失败呢”                     | “星桥的只读查询认证失败后是否重试” |
| 新会话直接问“那它呢”                       | 缺少可确定对象，返回澄清请求       |

示例只是教学预期，不是已测的模型输出。历史能帮助补全指代，也可能包含错误结论，因此改写只能补足原问题所需的对象，不能添加用户没有提出的条件或授权。

## 3. 决定这条输入该走哪里

路由是在进入检索前，决定请求交给哪条预先定义的处理流程。本课只设下面四种应用去向。

| 去向       | 适用情况                             | 应用动作                               |
| ---------- | ------------------------------------ | -------------------------------------- |
| 知识库查询 | 问题与资料主题有关且语义明确         | 生成独立问题，进入受范围限制的检索     |
| 简短交互   | 明确的问候或帮助请求                 | 返回固定问候或使用说明，不调用检索模型 |
| 需要澄清   | 指代或范围缺少必要信息               | 返回一个具体澄清问题，不检索           |
| 不支持     | 请求操作文件、执行命令或超出服务用途 | 明确说明范围，不执行所请求操作         |

前置规则可以先识别精确的问候和帮助命令，其余由一个受 Schema 约束的模型调用提出路由与独立问题。应用检查枚举、非空文本和长度。未知去向、异常结构或改写调用失败均停止并报告技术失败，不用原输入悄悄继续。

模型判断不能证明用户有权查看某份资料。即使输入声称“我是工作人员”，路由到知识库后仍只能在游客范围内检索。没有可见证据时给出“当前可用资料不足”的通用提示，不能透露隐藏文档的标题或存在情况。

本课把需要澄清与不支持加入应用响应状态，并在 HTTP 层正常返回明确结果。原有回答、依据不足和技术失败状态继续有效。

## 4. 多查询增加了什么

多查询，英文 Multi-query，指围绕同一个已明确的问题生成少量不同表述，各自检索后合并候选。它有机会补充原问题漏掉的词语，也会增加调用和查询工作。

本课保留原独立问题，再生成至多两个改写问题。去除空白和完全重复文本，所有问题沿用同一快照、身份和候选上限。生成变体失败时报告该策略失败，比较报告不能把它伪装成正常的单查询结果。

如果每个问题本身使用混合检索，先按第四课完成该问题的两路融合，再把不同问题的结果按相同 RRF 约定合并。同一片段在每个问题的排名中只计一次。合并候选截断到声明的 C 后，使用原独立问题进行一次重排，随后按第二课的预算选择证据。

```text
当前输入与已有历史 → 路由和独立问题
→ 原问题与最多两个变体 → 各自检索 → 合并去重并限制候选
→ 用原独立问题重排 → 选择证据 → 生成并验证回答
```

用于生成回答的用户问题仍保留原始表达，独立问题作为辅助上下文。记录变体数、检索次数、重排次数和总耗时。无法确认的省略问题先澄清，不能靠生成更多猜测掩盖缺失的信息。

## 5. 用对照实验判断是否值得保留

固定语料、问题、快照和模型设置，分别运行无重排、加重排、加多查询三个配置。多轮改写另外使用固定两轮对话，避免把没有历史的单轮问题算作同一任务。

逐题检查候选是否已经含有证据、最后送入模型的片段是否足够，以及回答是否受支持。报告各阶段耗时和调用用量。单次回答改善但平均成本明显增加时，说明适合哪些问题；没有收益时，可以在默认配置中关闭该策略，保留实验与回归用例。

## 6. 练习与验收

### 任务 1　接入可开关的重排

**目标。** 在保留初检记录的同时，重新选择进入生成流程的候选。

增加重排适配层与候选数量设置，接入检索及回答入口。输出长度不符、非有限分数或身份对应错误时拒绝结果，本课先明确报告失败，第七课再加入可选降级。

通过条件如下。

- 预设分数复现第一节的排序变化，重排只处理初检中的片段，不添加未检索资料。
- 应用入口驱动重排和证据选择，测试记录输入的问题、候选和调用次数。
- 同分按片段编号排序，非法分数实际到达检查后被拒绝。关闭重排时仍得到原初检流程的结果。
- 真实模型对比记录 Recall、MRR、耗时和用量；没有提供 Token 用量的模型记为不可得，不能填零冒充测量。

### 任务 2　接通连续对话、改写与路由

**目标。** 让第二轮输入能够使用应用保存的历史，并明确处理无需检索的请求。

增加创建会话及提交消息的入口，由应用保存每轮记录。实现第三节的四种去向，在知识库路径生成独立问题并调用已有回答流程。

通过条件如下。

- 从会话入口连续提交本课两轮问题，应用自行保存历史并把它传给改写调用，测试不得手动把第一轮答案塞进第二轮输入。
- 新会话的模糊指代进入澄清；问候和不支持请求不进入检索与生成。检查路由类别及执行记录。
- 一次技术失败被记录，后续可继续处理；异常文本不进入改写历史，保留窗口和预算按正文规则执行。
- 身份冒充文字无法扩大资料范围，不同身份不能读取或继续同一会话。未知路由与改写失败不会静默继续。

### 任务 3　实现有限多查询并做对照

**目标。** 用有限额外查询检查是否能找回原问题遗漏的证据。

接入最多两个变体、去重和分层融合，从同一应用入口运行第五节的对照实验。

通过条件如下。

- 原问题始终保留，重复与空变体不会额外检索。每个有效问题使用相同快照与可见范围。
- 流程测试验证合并名单、最终候选上限与一次重排，测试只控制外部返回，不替应用完成融合。
- 至少选择六个有不同表达特点的问题比较，记录候选变化、失败、耗时和额外调用成本。真实实验结论与替身测试分开。

### 知识检查

重排为何找不回初检遗漏的 E？独立问题可以补充什么，哪些信息必须来自身份上下文？同一个片段被三个变体找到，是否等于获得三份独立事实？

通过条件是能区分候选范围、问题语义与授权来源，并说明重复命中只反映检索路径。
