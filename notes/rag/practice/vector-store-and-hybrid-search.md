# 向量存储与混合检索

前几课的查询依靠进程内的数据。程序退出后，需要重新准备。资料增加时，逐块比较也会变慢。本课把保存和查询向量的工作交给一个存储服务，同时补上 BM25，与向量排名做一次可比较的融合。

完成后，同一入口可以选择向量、词法或混合检索，服务重启后仍能找到已发布的资料。三种方法都要遵守同一个可见资料范围。

## 学习前提与本课范围

复用第三课的资料快照与更新约定。BM25、稀疏表示和 RRF 的概念见[第二阶段第五课](../foundations/lexical-and-hybrid-search.md)，本课将它们接入应用。

路线允许 Qdrant 或 PostgreSQL 配合 pgvector。为了只学习一套服务接口，本课用 Qdrant 说明实现路径；已有其他选择时，可以按相同契约验收，不要求同时部署两套。

本课的词法评分先在应用中运行，小语料下容易检查。中文切词可以沿用第二阶段的规则，但必须保留词项出现次数。原先为计数基线生成的去重集合，无法提供 BM25 需要的词频。

## 1. 数据库接手什么

应用负责读取、清理、切块与编码，再把向量、身份和元数据交给数据库。查询时应用编码问题，数据库按指定范围返回候选，应用回查原文并继续使用第二课的回答流程。

以 Qdrant 的存储与查询接口为例，collection 表示一组可搜索的记录，point 表示一条带向量和附加数据的记录，payload 是该记录的附加字段。单个向量字段有自己的维度和距离配置。详见[集合文档](https://qdrant.tech/documentation/manage-data/collections/)。

| 应用信息                   | 保存用途                   |
| -------------------------- | -------------------------- |
| 片段编号、文档编号与版本   | 把结果对应到原文           |
| 资料快照与处理配置         | 检查查询使用哪一批记录     |
| 向量与编码模型信息         | 维持配套的比较方式         |
| 标题、来源、章节和字符区间 | 展示引用和回查             |
| 可见组                     | 限制本次查询可以使用的资料 |

Qdrant 的 point ID 支持无符号 64 位整数和 UUID，不能直接假定任意路径字符串都是有效 ID。应用可以用稳定映射生成数据库 ID，同时在 payload 保存原片段编号。[记录身份文档](https://qdrant.tech/documentation/manage-data/points/)给出了支持的形式。

数据库维度相同不代表编码模型兼容。应用仍要检查模型版本、输入规则、归一化和距离方法。更换这些条件时建立新的处理配置与快照，避免把旧向量和新向量混查。

向量索引帮助减少相似度比较，第二阶段已经介绍过 HNSW。元数据索引则帮助数据库按字段筛选记录。例如，Qdrant 的 payload 索引可用于可见组这样的过滤字段，字段类型要与保存的值相符。建集合后先准备需要的过滤索引，再写入数据，记录使用的向量索引与查询设置。索引有额外的内存和存储开销，不要求给每个展示字段都建索引。[Qdrant 索引文档](https://qdrant.tech/documentation/manage-data/indexing/)说明了两类索引的用途。

## 2. 持久化后仍要完整发布

本课继续采用串行摄取。可以为每个快照建立独立集合，准备完成后再更新应用持久保存的“当前快照”指针。原文与片段映射也必须持久保存，不能只留下向量。

写入已收到请求，不一定等于全部数据已经可查询。按所选服务与 SDK 的确认方式等待操作完成，再核对记录数量、身份及可回查性，最后发布。写入或核对失败时，保留当前指针。

片段较多时按固定批大小写入候选集合，避免一次发送全部向量。批大小是正整数，最后一批可以不足整批。中间一批失败时整次发布失败，已写入的候选数据仍不能被当前查询使用。记录失败批次与片段编号，重试同一批使用相同数据库 ID。

未变文档可以复用已生成的向量，再复制到候选集合，避免重复调用编码模型。删除文档时，候选快照不再包含它。旧快照保留到没有正在使用的查询和需要它的实验记录后，再由明确的维护操作处理；课程不要求自动清理历史。

这种按快照隔离的方式容易理解，也会占更多空间。它用于本课的小型项目，不要求把它当作所有系统的唯一发布方式。

## 3. 先确定哪些资料允许参与排名

第四课首次引入可见组。它是应用赋给文档的访问分类，片段继承文档的值。使用[权限材料](practice-materials.md#权限材料)，公开文档属于 `public`，内部教学文档属于 `staff`。

身份上下文表示应用已经认可的调用者身份及允许访问的组。本课的本机 HTTP 入口固定使用游客身份，工作人员身份只由测试中的可信身份提供器产生。请求正文不能自行声明工作人员权限。第七课再把该提供器接到真实认证结果。

查询处理依次进行下面三步。

1. 应用读取身份上下文，计算允许访问的组。
2. 向量和词法两路只在这些组内选择前 K 个候选。
3. 回查原文时再次确认快照与组一致，再把候选交给生成流程。

必须在选取 Top-K 时限制范围。先取全库前 K 个再删掉无权查看的片段，可能使本来可返回的公开候选全部被挤掉。

Qdrant 可用 payload 条件过滤，例如把当前快照与允许的可见组作为组合条件。具体条件语法属于 Qdrant 查询接口，见[过滤文档](https://qdrant.tech/documentation/search/filtering/)。应用组名与授权规则由本课程定义。

资料缺少可见组或值未知时不发布。记录测试身份只使用无现实身份信息的代号。此处证明资料范围过滤有效，尚不能证明外部用户身份已经可信。

## 4. 让词法评分使用真实词频

本课采用一个明确的 BM25 版本，避免不同库的默认值影响比较。检索文本由标题与片段正文组成，词项序列保留重复出现；查询词项去重后求和。

```text
IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))

score(q, d) = 对查询中的不同词项 t 求和
             IDF(t) × tf(t,d) × (k1 + 1)
             / (tf(t,d) + k1 × (1 - b + b × length(d) / avg_length))
```

N 是本次可见片段数，df 是包含该词项的可见片段数，tf 是它在当前片段中的次数。length 为片段检索文本的词项数，avg_length 为这些可见片段的平均长度。k1 控制词频饱和，b 控制长度调整。本课先固定 k1 为 1.2、b 为 0.75，再根据实际数据实验。

这里的正值 IDF 与 [Lucene 10.0 的 BM25Similarity 文档](https://lucene.apache.org/core/10_0_0/core/org/apache/lucene/search/similarities/BM25Similarity.html)所列形式一致。本课还明确了查询去重和可见范围内统计的选择，不要求分数与某个搜索产品逐位一致。

没有可见片段或平均长度为零时返回空结果。零匹配片段不返回；其余按分数降序、同分按片段编号升序排列。与第二阶段简单计数基线分开命名和记录。

先用三个词项序列检查计数。

| 片段 | 词项序列              | `retry` 的词频 | 长度 |
| ---- | --------------------- | -------------- | ---- |
| A    | `retry retry timeout` | 2              | 3    |
| B    | `retry log`           | 1              | 2    |
| C    | `log`                 | 0              | 1    |

对这三个可见片段，N 为 3，平均长度为 2，retry 的 df 为 2。查询 retry 时，A 约得 0.5666，B 约得 0.4700，C 不返回。若把每篇词项先去重，A 的词频和长度都会算错。

## 5. 两路排名怎样合并

本课把三种应用模式称为 `dense`、`sparse` 和 `hybrid`，分别表示稠密向量、BM25 词法和两路融合。这里 sparse 沿用词项稀疏表示的概念，不要求额外使用稀疏神经模型。

每一路先取候选数 C，C 不小于最终 K，再按片段编号合并。本课使用第二阶段的等权 RRF，名次从 1 开始，同一路中的同一片段只贡献一次。

```text
RRF 分数 = 各路中 1 / (c + 名次) 的和
```

c 为正的平滑常数，与候选数 C 分开。仍用 c 等于 1、词法排名 `[A, B, C]`、向量排名 `[C, B, D]` 手算，A、B、C、D 的分数分别为 1/2、2/3、3/4、1/4，融合排名为 `[C, B, A, D]`。

业务入口保留两路原排名与融合分数，方便解释结果。Qdrant 也提供原生融合查询，但本课先由应用按上述公式融合。采用产品原生融合时，应核对其名次起点、常数与权重语义，不能假设默认分数相同。[Qdrant 混合查询文档](https://qdrant.tech/documentation/search/hybrid-queries/)列出了相关参数。

## 6. 练习与验收

### 任务 1　接入持久存储和范围过滤

**目标。** 在重启后保留资料，并让查询只使用身份上下文允许的片段。

把第三课的准备、发布、更新、删除和回查接到存储适配层。新增可见组摄取校验与查询过滤，保留逐块比较的本地实现作为小样本参照。

通过条件如下。

- 从摄取入口写入，重启存储服务与应用后，从查询入口取得相同快照的原文和身份。
- 过滤索引的字段与类型符合记录约定，保存批大小和索引设置。跨两个批次写入时模拟后一批失败，确认候选集合没有提前发布。
- 更新、删除与准备失败仍遵守第三课约定，不发生部分发布。
- 使用三条不相等分数的预设向量，对照手算验证距离方向、过滤和回查；近似检索另记与精确排名的差异。
- D4 在未过滤时能成为最高分，游客请求却不会让它进入返回结果或生成证据；工作人员测试身份可以检索它。检查过滤条件和实际返回记录。
- 默认适配器测试不连接外部服务，真实数据库的持久化与过滤检查另外执行并记录版本。

### 任务 2　接入 BM25 与排名融合

**目标。** 用同一查询和同一可见语料比较两类检索信号。

实现本课 BM25 与 RRF，接到统一检索入口，并让回答入口复用该选择。沿用固定问题开展三种模式的对比。

通过条件如下。

- 词频样例和 RRF 样例与手算一致，零匹配、空集合、重复候选和分数并列有确定行为。
- 通过应用入口验证三种模式使用相同快照、组范围和片段回查，测试不替应用手工合并排名。
- 以同一组真实向量及人工标注比较命中和耗时，按第三课的原文证据口径报告结果，保留每路名单。
- 词法分数、向量分数与融合分数分别标记，不能混报为同一种相关概率。权限过滤在两路都生效。

### 知识检查

解释数据库 ID 与应用片段编号的关系。为什么同一维度的向量也可能不兼容？为什么权限过滤不能等到取完全库 Top-K 后才进行？

通过条件是能说明持久身份、编码兼容和候选范围三项约束，并指出真实数据库检查与替身测试各自证明的范围。
