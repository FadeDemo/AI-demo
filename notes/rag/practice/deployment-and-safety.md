# 部署、观测与安全

查询能在开发环境中返回答案后，还需要回答几件实际问题。数据库重启时会怎样，用户身份从哪里来，一次请求为什么慢，资料更新后缓存是否仍返回旧内容。本课把这些行为接到同一个 HTTP 服务中，再用故障演练检查。

完成后，你会有本机可启动的 Compose 部署、可追踪的请求记录，以及从请求入口验证过的身份和资料隔离。这些证据说明课程项目能按约定运行，适用范围仍是单机教学部署。

## 学习前提与本课范围

第四课已实现存储和可见范围过滤，第五课已接通会话与完整查询流程，第六课已定义运行记录。第一阶段的[超时、重试与并发](../../llm/streaming-and-reliability.md)继续复用。

本课新增可信身份接入、缓存与服务级保护，并把应用和数据库放入容器。不要求集群调度、统一登录平台或跨机分布式缓存。

## 1. 身份必须由应用认可的入口产生

认证判断调用者是谁，授权判断这个身份可以做什么。访问控制列表常简称 ACL，保存身份或组与可访问资料之间的关系。第四课已经用可见组实现授权范围，现在补上认证输入。

本课采用最小的服务端令牌映射。启动时从本地秘密配置读取随机测试令牌与身份、可见组、摄取权限的对应关系。客户端在请求头携带令牌，应用查表生成身份上下文。请求正文中的身份、组和管理员标记都不作为授权依据。

公开例子只写占位值，实际随机令牌不进入版本控制、日志或评测报告。认证失败返回 401，身份已确认但没有摄取或删除权限时返回 403。可见资料中没有答案时仍返回通用的依据不足，不透露隐藏资料是否存在。

摄取身份负责分配可见组，普通查询者无法修改它。会话编号也要检查所有者。历史已经包含的资料同样受权限约束；本课若检测到会话身份的组配置变化，要求创建新会话，避免把旧权限下的历史带入新请求。

```text
HTTP 请求 → 验证令牌 → 生成身份上下文 → 检查操作权限
→ 绑定资料快照 → 各路检索都限制可见组
→ 重排与生成只接收允许的候选 → 检查引用 → 返回结果
```

默认只绑定本机地址，数据库不向公网暴露。本课的令牌映射用于有限测试身份，若以后扩展公开服务，再处理 TLS、令牌轮换及集中身份管理。

## 2. 资料中的文字不能替应用授权

使用[注入材料](practice-materials.md#注入材料)，让攻击文字确实进入证据，观察应用是否继续保持原有规则。第二课已经分开应用指令与资料，并拒绝未知引用；本课还要检查它不能改变可见组、触发写入或泄露秘密配置。

资料不应获得执行命令、选择任意工具或下载链接的能力。本课程的 RAG 流程没有向模型提供这些执行入口，测试要据此检查调用记录。仅因为模型口头说“我不会泄露”，不能证明资料过滤有效。

输入分隔、输出检查、最小权限和运行监测需要配合使用。它们不能保证所有模型都抵抗所有变形攻击。[OWASP 的 Prompt Injection 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)列出了检索资料被污染的情形和多层防护思路。

## 3. 先实现范围清楚的缓存

缓存是保存计算结果，以便相同条件下重复使用。本课先缓存检索候选，不缓存生成回答，减少多轮历史与模型配置带来的额外变化。

缓存键至少包含规范化查询、检索方法及参数、编码配置、快照版本和身份的可见范围版本。缓存值保存片段身份与分数，返回前按当前快照回查并再次确认权限。键中可以保存查询摘要，日志不输出原问题。

设置有限存活时间，简称 TTL，到期后重新计算。快照改变或权限配置变化会形成不同键。不能只按问题文字缓存，否则工作人员查过的内部结果可能被游客命中，更新后的查询也可能使用旧资料。

问题向量可以在一次请求内复用。跨请求缓存问题编码属于可选优化，本课不要求额外实现。缓存损坏或回查不一致时删除该条应用缓存并重新检索，返回可诊断记录，不使用不明来源的数据。

## 4. 给整次处理一个停止时间

截止时间表示整次请求允许处理到什么时候。应用在入口设定它，每一步开始前计算剩余时间，下游超时不得超过这个剩余额度。有限次数的重试和退避等待同样要计入预算。

假设请求预算为 3 秒，已经处理 2.2 秒，下游建议等待 1 秒后重试。剩余 0.8 秒不足以完成等待，应用应停止并记录超时，不能重试后再另起一段 3 秒预算。测试使用可控时钟和等待替身，避免真实睡眠。

并发限制表示最多允许多少个请求同时使用某项资源。本课分别为生成调用和摄取设置上限，摄取仍保持单写入者。队列等待计入请求预算，容量不足或等待超时有明确结果。任务结束、异常和取消时释放占用，后续请求不能被泄漏的计数永久挡住。

处理规则沿用第一阶段的重试分类。查询可以在剩余预算内有限重试；摄取重放必须遵守第三课的身份和发布约定，不因响应丢失而重复发布不一致版本。

| 失败阶段                 | 本课行为                                                     |
| ------------------------ | ------------------------------------------------------------ |
| 检索存储不可用           | 返回依赖失败，不绕过过滤扫描未知资料                         |
| 重排超时                 | 若配置允许且仍有预算，使用已过滤初检排名并标记降级；否则失败 |
| 生成超时或输出验证失败   | 返回技术失败，不把候选文字当成完整回答                       |
| 摄取准备失败             | 保留当前快照并报告失败                                       |
| 客户端取消或请求预算耗尽 | 停止后续阶段，释放资源，记录停止原因                         |

降级是某个可选步骤失败后，采用已经约定且范围更小的处理方式。重排降级只改变候选顺序，不能取消权限、快照或证据预算检查。

本课程在 HTTP 层将总超时映射为 504，依赖不可用映射为 503，并发容量拒绝映射为 429；第二课的输出验证失败仍为 502。这些都是应用选择，响应使用稳定类别，错误正文不得暴露内部秘密。

## 5. 从一个编号找到各阶段记录

第一阶段的请求编号关联一次逻辑请求。追踪 Trace 则记录请求内部的调用关系，Span 表示其中一项有开始和结束时间的工作。OpenTelemetry 使用这些概念关联各操作，见[追踪说明](https://opentelemetry.io/docs/concepts/signals/traces/)。

本课至少记录一个请求级追踪及检索、重排、生成的子操作。未发生的操作不伪造成功记录。可以使用 OpenTelemetry 的本地导出器，不要求提前搭建外部观测平台。

| 记录     | 内容                                           |
| -------- | ---------------------------------------------- |
| 请求记录 | 请求编号、追踪编号、最终状态、总耗时           |
| 操作记录 | 阶段名、父操作、开始结束时间、失败类别与重试数 |
| 配置记录 | 快照、处理配置、模型标识、检索方式             |
| 用量记录 | 各模型调用的输入输出 Token，未知值明确标识     |
| 保护记录 | 缓存命中、超时、取消、并发拒绝与降级原因       |

使用白名单字段输出日志。测试故意让依赖异常带有虚构的秘密标记，确认标准输出、标准错误和追踪导出都不包含它。异常不能未经清理就整段写入日志。评测正文放在第六课专门的材料中，与运行日志区分。

## 6. 用 Compose 启动服务

容器镜像描述应用运行所需的文件和环境，容器是镜像的一次运行实例。Docker Compose 用一个配置描述多个服务、网络和数据卷，数据卷保存需要跨容器重建保留的内容。

本课部署 API 与第四课所选数据库。模型可以继续使用已有外部接口或本地模型目录，不要求再搭一个推理服务。锁定依赖和镜像版本，模型缓存提前准备，记录网络与硬件条件。

应用镜像不包含密钥、个人资料、开发环境目录或评测输出。秘密通过运行时注入；例如 Docker Compose 的 `secrets` 可以把秘密文件仅提供给被授权的服务，具体用法见[秘密管理文档](https://docs.docker.com/compose/how-tos/use-secrets/)。该标识符属于 Compose 配置。

容器开始运行时，数据库可能尚未准备好。健康检查用于确认依赖可以处理请求。Compose 的依赖条件 `service_healthy` 可配合 `healthcheck` 等待就绪，详见[启动顺序文档](https://docs.docker.com/compose/how-tos/startup-order/)。应用本身仍需处理运行期间的依赖失效。

为应用提供就绪检查，确认必要配置和存储可以使用，再允许接收请求。此检查不需要调用付费模型。启动、等待就绪、停止和清理命令写入 README，数据卷删除必须与普通停止分开说明。

## 7. 练习与验收

### 任务 1　接入身份并隔离缓存

**目标。** 让每次 HTTP 请求得到可信的身份上下文，缓存复用也遵守同一边界。

配置游客、工作人员和摄取者三个教学身份，连接第四课的可见组过滤，实现第三节的候选缓存。

通过条件如下。

- 从 HTTP 入口验证有效、无效和缺失令牌，普通查询者不能摄取或删除，正文伪造组无效。
- 工作人员先查 D4，再用游客查询同一问题，候选、重排输入、生成输入和返回引用都没有 D4；确认缓存确实被访问并区分身份范围。
- 更新、删除、TTL 到期和权限配置变动后不复用不合适的缓存。组变化后的旧会话无法继续读取历史。
- 注入材料实际进入模型证据，不能改变应用权限或触发不存在的执行能力；非法引用仍被第二课的检查拒绝。

### 任务 2　接通预算、并发与运行追踪

**目标。** 请求失败或等待过久时能够停止，并留下可定位的记录。

实现第四节的服务级截止时间、并发上限、取消与降级约定，将追踪和白名单日志贯穿真实应用流程。

通过条件如下。

- 从 HTTP 入口注入存储失败、重排超时、生成失败、取消和容量耗尽，检查状态类别、已执行阶段与未执行阶段。
- 用可控时钟复现 3 秒预算的例子，退避不会越过截止时间，重试数有上限。
- 取消或异常后占用被释放，下一请求仍能运行。摄取失败不会更改当前快照。
- 同一请求的日志和追踪能够对应，必要字段齐全，Prompt、资料正文、令牌和异常中的虚构秘密标记不出现。

### 任务 3　部署并做一次故障演练

**目标。** 换一个环境仍能依照说明启动、使用和停止应用。

编写镜像与 Compose 配置，使用运行时秘密和持久数据卷。按 README 启动后，以真实 HTTP 请求摄取公开教学资料，再检索与回答。

通过条件如下。

- 健康检查通过后可使用三个 API，重启数据库和应用后资料仍存在，片段身份与快照可回查。
- 在自己启动的教学服务中短暂停止数据库，检查依赖失败、恢复后的可用性和追踪记录；不操作个人正在使用的其他服务。
- 默认离线测试、格式与 lint 检查通过，真实模型、数据库及容器验证分别有记录。
- README 包含依赖、秘密占位说明、启动停止、测试、评测、失败处理与适用范围，附数据流图和 3～5 分钟演示。
- 结束演练后停止本次启动的服务，确认没有残留的任务进程；保留有用的数据卷和评测产物。

### 知识检查

为什么令牌有效仍可能无权删除文档？缓存键只包含问题会出现什么错误？重排可以降级时，哪些检查仍然必须继续执行？

通过条件是能从身份产生、资料过滤一直说明到缓存和生成边界，并区分启动就绪与运行期间可靠性。
