# 数据摄取与切块策略

一份手册里有标题、条件、结论和代码。固定长度切分容易把它们拆开。资料更新后，已有片段还可能保留被替换的规则。本课分别处理切块质量与内容更新，让查询使用能够回查的当前资料。

完成后，项目能切换三种切块策略，按文档更新或删除资料，并用固定问题解释策略变化带来的影响。

## 学习前提与本课范围

第一课已经保留字符区间，第二课已经有批量摄取与查询入口。本课继续使用 TXT 和结构简单的 Markdown。摄取在单进程内串行进行，发布期间的查询读取上一份完整集合。

这里的资料快照指某一时刻可查询的完整文档、片段、向量及配置集合。每次查询在开始时绑定一个快照，直到回答结束都使用它。第三课先在内存中实现，第四课再保存到数据库。

## 1. 三种切法分别保留什么

| 策略       | 怎样切                         | 容易检查的收益           | 需要留意的代价             |
| ---------- | ------------------------------ | ------------------------ | -------------------------- |
| 固定长度   | 按字符区间前进，可保留重叠     | 长度可控，位置直接计算   | 句子与条件可能分离         |
| 标题与段落 | 先识别章节，再组合相邻完整段落 | 同一小节的语义较容易保留 | 单段过长时仍需拆分         |
| 递归切分   | 超长部分逐级尝试更细分隔       | 优先保留较完整的文本单位 | 规则和分隔符保留方式更复杂 |

本课为三种方法规定共同的字符上限 L。标题与段落策略先按 Markdown 标题建立章节，再把本节相邻段落顺序组合到不超过 L，无法容纳的单个长段落退回固定长度切分。组合时保留原有分隔符，不能把不相邻的正文拼成一个声称连续的区间。

递归切分对超长文本依次尝试空行、句末标点、字符切片。每一级只继续拆超过 L 的部分，再按原文顺序合并相邻单元到 L 以内。保留分隔符属于哪一侧，并用区间回查测试确认没有漏字。本课结构切分先不增加重叠，固定长度策略可单独比较重叠为零与非零的结果。

这两套规则是本课的教学实现，不等同于某个框架中同名类的全部行为。中文标点、换行和代码块都需要实际样例验证。

## 2. 标题可以帮助阅读，也会改变编码输入

以[教学材料 D1](practice-materials.md#文档-d1)为例，重试段单独拿出来时，读者需要知道它来自“请求处理”的“重试”小节。

父子结构指文档包含章节，章节包含片段的关系。本课在片段中保存文档编号和章节标题路径。文档标题、章节路径与片段正文可以共同组成编码输入，但正文区间仍只对应原始规范化文本。

课程练习先识别不在代码围栏内、行首一至六个 `#` 后接空格的 Markdown 标题。纯文本及无标题部分使用空的章节路径。标题路径在每个片段的起点确定；固定长度块若跨章节，额外记录涉及的章节，或在章节边界结束该块并明确记录策略变化。

代码围栏内部的 `#` 不当作章节标题。超长代码块允许按字符拆开，但记录“代码块被拆分”，不宣称保留了完整代码语义。复杂 Markdown 扩展语法不作为本课必需支持范围。

## 3. 先分清三个版本

| 版本         | 何时改变                         | 解决的问题                         |
| ------------ | -------------------------------- | ---------------------------------- |
| 文档版本     | 规范化正文或影响检索的元数据改变 | 回查引用指向哪份文字               |
| 处理配置版本 | 清理、切块或编码规则改变         | 解释相同原文为何产生不同片段或向量 |
| 资料快照版本 | 一批更新成功发布                 | 保证一次查询读取一致的资料集合     |

文档编号继续标识同一份逻辑资料，正文修改不会把它变成另一份文档。内容摘要是从完整规范化内容计算出的摘要值，可用于检测相同内容。应用同时比较标题、来源及其他会影响检索的元数据；仅正文相同不足以说明记录完全相同。

同一编号、同一内容和配置再次摄取时，可以复用已有片段与向量，不增加重复记录。同一编号变更内容时，生成新文档版本。不同编号即使文字相同也保留各自来源，本课不自动合并跨来源资料。

片段身份包含文档版本和处理配置。改变切法后产生新的片段身份，旧实验报告仍使用旧快照解释，不能用新片段覆盖旧报告中的引用。

## 4. 更新成功后才让查询看见

沿用第二课“整批准备成功后发布”的约定，新增按文档更新与删除入口。以下步骤由应用执行。

1. 读出当前快照和更新清单，检查重复编号、目标文档及输入格式。
2. 找到新增、变更、未变和待删除的文档。仅对需要重建的记录切块并编码。
3. 在候选快照中完成所有变更，验证片段、向量和原文能够互相对应。
4. 全部成功后把当前快照指向候选快照，后续查询使用它。

准备失败时保留当前快照，并返回失败原因。删除也通过发布新快照生效。发布过程中已有查询继续使用它绑定的旧快照，避免检索用旧资料而引用回查用新资料。

用 D1 的 `v1` 和 `v2` 做一次预测。更新前 q1 的依据是最多三次尝试，更新发布后是最多两次。若新版本编码失败，后续查询仍应看到三次，并且更新请求明确报告失败。不能同时出现“更新失败”和“旧文档已经消失”。

HTTP 可以扩展本课程的 `/ingest` 请求，提供明确的全量替换与按编号更新模式，再增加删除请求。操作名称由应用约定并写入 README；测试必须通过这些入口驱动，不能直接改内部字典来代替应用更新。

## 5. 怎样公平比较切块

先选至少六个问题，覆盖单段事实、跨段条件、跨文档依据、精确标识符、无答案和边界附近的事实。每题在固定文档版本上标出回答所需的原文区间。

本课把一段必须完整读到的原文区间称为证据单元。一个问题可以需要多个单元。标注单位保持在原文上，切法变化时无需重新把所有片段当作相关答案。

本课的证据覆盖率按以下方法计算。

```text
完整覆盖的证据单元数 / 该题必需证据单元总数
```

检查同一文档内返回片段区间的并集是否覆盖某个单元。重叠部分只算一次，跨文档区间不能拼在一起。无答案问题没有必需单元，覆盖率记为不适用，单列返回内容。

先比较检索前 K 块覆盖了多少，再比较第二课预算选择后实际送入模型的块覆盖了多少。两处范围不同，分别报告。覆盖率只说明文字是否齐全，零散片段读起来是否连贯仍需人工核对。

固定文档、问题、Embedding、查询编码、K 和生成预算，一次只改切块策略。报告片段数量、重复字符比例、准备时间、查询时间和证据覆盖。若生成回答，也保留对应模型配置。数字来自自己的实验，不提前写哪种切法必胜。

## 6. PDF 先检查能读出什么

PDF 页面中的可见文字可能有复杂的排布，提取顺序会影响上下文。扫描件的文字常保存在图片中，需要光学字符识别，简称 OCR，才能得到候选文本。以 pypdf 为例，其[文本提取文档](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)说明了扫描图片、页眉页脚与布局带来的限制。

本课只做输入诊断练习，不要求实现完整 PDF 或 OCR 管线。下面是教学模拟的提取结果。

```text
星桥使用手册 第 1 页
查询最多等待五秒。
星桥使用手册 第 2 页
认证失败  每月价格
立即停止  暂未提供
```

前两行页眉需要与正文区分，后两行可能来自并排两栏。单纯按换行拼接会把认证失败与价格凑在一起。遇到表格还要核对表头与单元格，遇到乱码先报告提取失败。缺失文字不能靠切块补回来。

## 7. 练习与验收

### 任务 1　接入可比较的切块策略

**目标。** 用同一份资料比较文本边界，不改变查询入口的基本行为。

实现本课三种策略和章节路径，记录字符上限、重叠及分隔规则。准备含标题、无标题、超长段落、代码围栏和连续空行的小材料。

通过条件如下。

- 文档准备入口可选择策略，查询结果仍能按区间还原原文，没有遗漏或跨文档拼接。
- 标题层级、代码围栏和超长单元遵守正文规则，片段不超过声明的字符上限。
- 同一输入与配置可复现，改配置后片段身份可以区分。编码前继续检查模型长度限制。

### 任务 2　发布更新与删除

**目标。** 让应用处理资料变化，并保留一次查询所依赖的完整快照。

实现上述更新流程，通过摄取入口发布 D1～D3，再更新 D1、重复提交相同内容并删除 D2。

通过条件如下。

- 从查询入口能观察到 q1 使用 D1 的新版本，q3 不再返回已删除 D2 的片段。
- 相同记录重放不增加条数，不重复编码；变更记录只重建需要改变的部分。
- 注入编码失败时，失败实际发生在候选准备中，当前快照保持完整。测试核对失败类别和发布记录。
- 用可控暂停点模拟发布中的查询，证明同一次请求的检索、模型证据和引用来自同一快照，无须启动真实并发服务。

### 任务 3　写一份切块对比报告

使用至少六个固定问题和真实 Embedding 比较三种策略，按第五节记录两处证据覆盖与成本。挑两题逐段解释差异，再对 PDF 模拟材料写出应检查的解析问题。

通过条件是材料与配置可复现，原文标注可定位，结论只针对已测数据；没有改善也保留结果。此任务以实验分析为主，离线测试不能代替真实编码结果。

### 知识检查

解释文档版本、处理配置版本和快照版本的区别。说明为何删除后不能只移除文档原文，却留下可被查询命中的片段。为什么比较切法时，应把必要证据标在原文上？

通过条件是能追踪更新如何影响片段、向量、查询与引用，且不会把不同切法的片段总数误当作同一个召回分母。
