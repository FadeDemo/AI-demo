# RAG 检索基础

给程序一批文档，再问它一个问题，程序应该先把可能有用的文档找出来。本专题就把这件事做完整。完成后，你会得到一个能比较关键词检索与向量检索的小程序，并能拿出固定问题、人工标注和计算结果，说明两种方法各自找到了什么、漏掉了什么。

RAG 指先检索资料，再让生成模型结合资料回答问题。这里先把向量看成一串有顺序的数字，Embedding 模型负责把文字转换成这些数字，供程序比较。第二、三课会分别讲清计算与模型用法。

这是 [roadmap 第二阶段](../roadmap.md#5-第-2-阶段rag-的最小理论前置第-2-周)的配套课程。第一阶段已经练习了如何调用模型、验证输出和记录运行情况。本阶段把注意力放到送给模型的资料从哪里来，最终返回检索结果，尚不生成回答。

文中的模型用法和检索方法附有原始资料。手算用的小向量、固定排名和交互实验里的数值都是教学数据，不能当作真实模型的测量结果。

## 学习前提

- 能用 Python 读取 UTF-8 文本，把一条记录表示成有明确字段的数据，并处理读取失败。
- 会在项目自己的环境中运行程序，知道依赖清单和锁文件的作用。
- 能写不访问网络的自动化测试，并区分测试替身与真实模型的运行结果。
- 学过 [LLM 使用基础](../llm/index.md)，理解 Token、模型输入限制和不可信资料的含义。

本专题从数字列表和最简单的相似度计算讲起，不要求先学完线性代数或训练神经网络。

## 学习顺序

| 顺序 | 课程                                               | 做完能观察到什么                                      |
| ---- | -------------------------------------------------- | ----------------------------------------------------- |
| 1    | [文档与关键词检索](retrieval-and-documents.md)     | 输入问题，得到按关键词匹配数排列的文档                |
| 2    | [向量与相似度](vectors-and-similarity.md)          | 能算出两个向量的相似度，并解释排序方向                |
| 3    | [Embedding 与逐篇检索](embeddings-and-search.md)   | 用真实 Embedding 表示文档和问题，返回相似度最高的文档 |
| 4    | [检索评测](retrieval-evaluation.md)                | 用 20 个固定问题比较两种检索，留下可复查的报告        |
| 5    | [词法检索与排名融合](lexical-and-hybrid-search.md) | 能解释 TF-IDF、BM25，并手算两份排名的融合结果         |

前四课完成本阶段要求的检索实验。后两课用短例子和书面分析介绍后续会用到的方法，不要求提前安装搜索服务或接入重排模型。

## 用一个小项目连续练习

实现任务放在计划中的 `projects/rag-knowledge-base/`。开始第一课的实现时再创建项目和依赖文件，后续沿用同一个项目。已有终端助手保留第一阶段的功能；本专题不要求把文档检索加进聊天入口。

代码、测试、语料、模型配置和完整评测结果放在项目中。每课的观察结论与知识检查，在实际作答时才建立个人回答文件。课程里的任务已经写全，不需要预先准备答题模板。

练习采用 Python。向量计算优先用 NumPy；Embedding 可以使用本地模型，也可以使用明确支持文本向量的服务。选定依赖后，由项目自己的清单和锁文件记录。各课会先讲清输入与输出，再要求你接通相应入口，不限定类名或文件拆分方式。

### 本阶段对文档作出的简化

语料由 50～100 篇短文档组成，一份文件算一篇文档。文档必须能完整放入所选 Embedding 模型的输入限制内。本阶段以整篇文档计算相关性，方便逐篇核对人工标注。长文档切块、PDF 解析和资料增量更新放到后续 RAG 实战。

这个选择会限制实验结论。你可以判断这批短文档上的结果，不能据此断定同一种方法也适合长手册、复杂表格或所有领域。

### 各项实现怎样接起来

| 任务         | 复用的前置能力             | 本次新增行为                     | 触发入口与验收证据                                       |

| 第一课任务 2 | 已载入的文档集合           | 对问题分词、计分并返回关键词排名 | 单次检索入口驱动，检查文档编号、分数和顺序               |
| 第二课任务 1 | 数字列表与基础测试         | 计算和校验向量相似度             | 直接调用计算组件，用手算值验证                           |
| 第三课任务 1 | 文档记录与向量计算         | 按文档和问题的不同用途生成向量   | 文档准备入口与查询入口分别调用相应编码步骤               |

第四课任务 1 是人工标注，后两课是书面分析。它们各自有独立的学习目标，不另设只做格式化或补测试的实现任务。

## 配套交互实验

[检索基础交互实验](../../projects/retrieval-usage-lab/index.html)可以直接在浏览器打开，所有计算都在本地完成。

- 调整向量方向与长度，比较余弦相似度、点积和欧氏距离。
- 移动相关文档的位置，观察 Recall@K、Precision@K 和 RR@K 怎样变化。
- 调整排名融合的常数，核对每一路排名贡献了多少分。

每课都会给出具体操作和需要解释的现象。实验不调用 Embedding 模型，也不代替你要实现的检索程序。

## 本阶段的综合验收

### 程序与实验

1. 固定保存 50～100 篇短文档，每篇都有唯一编号和可定位的原文。两种方法使用同一批文档、同一份标题与正文。
2. 同一检索入口接收问题、检索方法和正整数 K，返回文档编号、标题、来源、分数与原文。关键词零匹配返回空列表，向量检索的高分不被解释为资料一定能回答问题。
3. 文档与问题使用兼容的 Embedding 模型和输入方法。真实实验记录模型版本、输入前缀或指令、向量维度、归一化方式与输入长度处理。
4. 固定 20 个问题，人工标注每题的相关文档及依据，包含同义表达、精确标识符和资料无答案的情况。
5. 按第四课的统一口径报告 K 为 1、3、5 时的 Recall@K、Precision@K 和 MRR@K。另列无答案问题的结果，不把它们混入有答案问题的均值。
6. 保留逐问题排名与耗时，选至少三个有分析价值的例子，核对原文、标注和两种排名。允许两种方法都表现不错，不要求凑出向量检索必胜的结论。

### 自动化检查

默认测试使用小文档和预设向量，不下载模型、不访问网络、不需要密钥。应覆盖文档编号、关键词规则、相似度计算、排序与并列处理、非法向量、指标分母和无答案约定。各课的测试要求都归入相应实现任务。

单次检索和批量评测的流程测试，应从项目公开的处理入口驱动。直接调用相似度函数只能证明计算组件正确；在测试里手动把向量接到排名上，不能证明应用已接通文档准备和查询。

真实 Embedding 的手动实验单独记录。用预设向量通过测试，可以证明排序与流程符合约定；两种方法在真实语料上的差别，要由真实编码后的固定评测来说明。

### 知识与复现

你需要能解释维度相同为何不足以保证向量兼容，为什么不同评分方法的原始分数不能随意相加，以及 Recall@K 与 MRR@K 分别遗漏了哪种信息。还要能区分倒排索引、近似向量检索、排名融合与重排各自负责的工作。

项目 README 写明环境准备、文档准备、单次检索、批量评测、测试和质量检查的实际命令。换一个人应能根据这些说明重跑实验，并找到报告里引用的原文。格式化、lint 和自动化测试通过后，再核对真实实验记录与书面分析。

完成这些内容后，继续 [roadmap 的 RAG 实战主线](../roadmap.md#6-第-3-阶段8-周-rag-实战主线)。把本阶段已有的文档编号、检索入口和评测集接着用，下一阶段再加入切块、基于资料生成回答和引用展示。
