# 文档与关键词检索

先做出一个很小的结果。用户输入“请求超时”，程序从目录里找出谈到请求超时的文件，并告诉用户文件在哪里。这个过程还不需要调用模型。

本课完成后，你会有一批编号稳定的文档，以及一个能返回关键词排名的检索入口。后面的向量检索和评测都复用它们。

## 1. 检索先返回资料

检索负责从一批资料中找出与问题有关的内容。用户提供的搜索文字称为查询，英文常写作 Query。被搜索的资料称为文档，英文常写作 Document。所有待搜索文档合在一起，称为语料集合，后文简称语料。

在问答场景中，一次处理可以分成下面几步。

```text
用户提出问题
→ 检索程序找文档
→ 应用把找到的资料与问题交给生成模型
→ 模型生成回答，应用检查并展示
```

本阶段完成前两步。你应当看得到原文与来源，随后才能判断资料是否有用。模型回答得流畅，不能替代这一步检查。

检索程序通常会给每篇文档打分，再按分数排列。暂时选出来、准备进一步检查的文档叫候选文档。Top-K 表示取排名最前面的 K 篇，K 由调用方指定。它只限制返回数量，不保证这些文档都相关。

## 2. 先让每篇文档找得到

本课采用 UTF-8 的 `.txt` 或 `.md` 文件，一份文件算一篇短文档。本次交给文档准备入口读取的目录称为语料根目录。程序读出文件后，至少保留下面四项。

| 字段     | 含义                       | 为什么需要                       |
| -------- | -------------------------- | -------------------------------- |
| `doc_id` | 文档的唯一编号             | 后面用它对应向量、排名与人工标注 |
| `title`  | 展示用的标题               | 用户可以快速辨认文档             |
| `text`   | 文件的正文                 | 检索计算和人工检查都用得到       |
| `source` | 相对于语料根目录的文件路径 | 能回到原文核实内容               |

这些描述文档身份和来源的信息称为元数据。正文保留资料内容，元数据帮助程序和人找到这份内容。

为减少本课的文件解析工作，标题先取文件名去掉扩展名的部分，正文保留完整文件内容。统一换行符并清除正文首尾空白即可，不要求解析 Markdown 标题或 YAML。

编号可以直接采用包含扩展名的相对路径，与 `source` 一样，以语料根目录为起点。例如，语料根目录为 `data/docs/`，文件为 `data/docs/network/超时.md`，编号就是 `network/超时.md`。不要使用当前遍历次序作为编号，否则多放一个文件就可能改变原有编号。

空文件不加入语料，并记录跳过原因。文件读取或 UTF-8 解码失败时，文档准备应明确失败，不能悄悄减少实验文档数。先用三个文件走通读取，再扩大到 50～100 篇。每篇围绕一个较小主题，保留来源与使用许可；个人记录中的密钥、私人信息和不适合公开的内容不要用作练习资料。

下面三条是专门为手算编写的教学文档。假设三个文件都直接放在语料根目录中，编号就与包含扩展名的文件名相同。

| 编号      | 标题 | 正文                     |
| --------- | ---- | ------------------------ |
| `超时.md` | 超时 | 请求超时后有限重试。     |
| `日志.md` | 日志 | 记录请求耗时与超时类别。 |
| `预算.md` | 预算 | 发送前检查上下文长度。   |

## 3. 给关键词匹配定一个算得清的规则

关键词检索根据查询与文档中出现的文字寻找结果。先采用一个容易检查的计分办法，后面才有可以比较的起点。实验中供其他方法比较的这套固定做法，称为基线。

### 把文字拆成检索词项

检索词项是用于匹配的文字单位。它可以是一个词，也可以是按明确规则截取的字符片段。这里的切分服务于关键词检索，与第一阶段模型使用的 tokenizer 分开处理。

中文句子通常没有词间空格。本课先用连续两个汉字组成的片段匹配，不引入额外的中文分词库。规则固定如下。

- 对拉丁字母做大小写统一。连续的英文字母、数字与下划线作为一个词项，例如 `REQUEST_TIMEOUT` 统一为 `request_timeout`。
- 每一段连续汉字按相邻两个字切分。`请求超时` 得到 `请求`、`求超`、`超时`。一段只有一个汉字时保留这个字。
- 空格、换行和其他标点只分隔片段，不把两侧文字拼成一个词项。查询和文档都采用同一规则。

这个切分办法会产生“求超”这样不成词的片段，也可能把有区分作用的标点拆开。它适合本课建立可检查的基线。第五课会讨论这些选择对词法检索的影响。

### 只数命中了几个不同词项

先取查询的不重复词项集合，再取文档标题、换行和正文组成的文本中的词项集合。文档分数等于两个集合交集中词项的数量。同一个词在文档里出现十次，在这条规则下仍只算一次。

```text
查询词项 = {请求, 求超, 超时}
超时.md 命中 {请求, 求超, 超时}，分数为 3
日志.md 命中 {请求, 超时}，分数为 2
预算.md 没有命中，分数为 0
```

按分数从高到低排列，零分文档不返回。分数并列时按 `doc_id` 的字符串升序排列，让相同输入产生稳定结果。K 超过正分文档数量时，只返回实际匹配的文档。

空查询或切分后没有词项的查询返回空列表。K 必须为正整数；无效时在检索之前返回明确错误。这些是本课采用的输入输出约定，后续向量入口沿用 K 的检查。

## 4. 先看一次失败会更容易理解后面的课

假设查询改成“连接一直没回应”。它与“请求超时”可能在谈同一种问题，文字却差别很大。按刚才的规则，程序可能找不到那篇超时文档。记录这个现象即可，不必立即加一份同义词表把它补掉。

另一个查询可能包含 `REQUEST_TIMEOUT` 这样的精确标识符。按标识符匹配，往往更容易找到明确提到它的文档。两种查询的差别，会在后续固定评测中实际检查。本课的小例子只解释规则，不预告真实模型一定会怎样排序。

分数 3 只说明命中了三个词项。它不代表 75% 的相关概率，也不能直接与后面余弦相似度的 0.8 比大小。

## 5. 练习与验收

### 任务 1　载入可核对的文档集合

**目标。** 为后续检索提供编号、正文和来源，避免排名出现后找不到原文。

在配套项目中增加文档准备入口。先用上面的三个小文件，再载入 50～100 篇短文档。把支持的目录范围、文件类型、编号规则和跳过空文件的规则写入项目 README。

通过条件如下。

- 同一批文件重复读取，编号、标题、正文和来源保持一致；增加其他文件不会改变已有文档的编号。
- 能查看载入数量并按编号找回原文。空文件会被跳过，读取失败或解码失败会明确报错。
- 用小目录测试上述行为。测试只读自己构造的练习文件，不依赖个人电脑上的资料。

### 任务 2　接通关键词检索入口

**目标。** 让用户的问题经过实际程序得到可检查的排名，作为第三课的比较对象。

复用任务 1 的文档集合，实现本课的切分与计分规则。检索入口接收查询、检索方法和 K。本课先只支持关键词方法；返回项至少包含文档编号、标题、来源、分数与原文。方法名称和命令形式由项目 README 明确记录。

通过条件如下。

- 从检索入口输入“请求超时”，上面三篇教学文档返回 `超时.md` 与 `日志.md`，分数分别为 3、2，`预算.md` 不出现。
- 重复词项不会重复加分，大小写统一生效，标点两侧不会错误拼接。并列结果按编号排序。
- 无匹配、空查询、K 超过结果数与无效 K 都符合本课约定。测试覆盖这些行为，并有从检索入口驱动的用例。
- 实际语料至少试查三个问题，保留查询、返回编号和简短观察。单次结果好坏都如实记录。

测试和格式检查归入这两个任务的收尾。仅写出切分函数的测试，尚不能证明任务 2 的文档加载、计分与结果返回已经接通。

### 知识检查

解释文档编号与标题各自的用途。再用本课三篇文档说明为什么零匹配可以返回空列表，以及为什么命中词项多仍可能找错资料。
