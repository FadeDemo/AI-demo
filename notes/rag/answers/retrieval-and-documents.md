## 知识检查

### 文档编号与标题各有什么用途

`doc_id` 让程序确定一条检索结果对应哪篇文档，回查原文和记录人工标注时都能用它。编号在同一批语料中必须唯一，加入其他文件后，已有文档的编号也应保持不变。本课用包含扩展名的相对路径作为编号。

`title` 供人阅读，帮助使用者快速辨认文档的主题。本课取文件名去掉扩展名的部分作为标题，因此 `超时.md` 的标题是 `超时`。标题可以重复；遇到同名文档，程序仍按各自的编号区分它们。

### 为什么零匹配可以返回空列表

只在课程的 `超时.md`、`日志.md`、`预算.md` 三篇文档中查询“向量数据库”，查询词项与每篇文档的标题、正文都没有交集，三篇文档的分数都是 0。按本课约定，零分文档不返回，因此结果是空列表。

K 限制最多返回多少篇，不要求凑满结果。即使 K 为 5，也可以一篇都不返回。空列表只说明这次没有词项匹配，不能单凭它断定资料中一定没有含义相关的内容。

### 为什么命中词项多仍可能找错资料

仍用这三篇文档，把问题换成“请求超时后该记录什么”，按本课规则会得到下面的分数。

| 文档      | 命中的查询词项         | 分数 |
| --------- | ---------------------- | ---- |
| `超时.md` | 请求、求超、超时、时后 | 4    |
| `日志.md` | 记录、请求、超时       | 3    |
| `预算.md` | 无                     | 0    |

`超时.md` 排在前面，正文却只说“请求超时后有限重试”，没有说明该记录什么。`日志.md` 的分数低一分，正文提到记录请求耗时与超时类别，对这个问题更有帮助。`预算.md` 讲发送前检查上下文长度，这次没有命中词项，也不回答记录什么的问题。

这套计分规则只数命中了多少个不同词项，没有判断文档是否回答了问题中的“该记录什么”。高分能帮助筛选候选文档，是否找到合用的资料，还要对照问题阅读原文。
