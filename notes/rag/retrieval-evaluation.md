# 检索评测

两种检索都能列出文档以后，最容易出现的做法是各试两句，觉得某一种“比较懂我的意思”。本课把判断所需的资料保存下来，让结果可以逐条核对。

做完后，你会有 20 个固定问题、人工相关性标注，以及一份来自实际检索入口的对比报告。只评文档检索，还不评价模型生成的最终答案。

## 1. 先决定什么叫找对

每个问题都需要一份相关文档清单。人工标注指由人查看问题和原文，决定哪些文档符合规定，并记录依据。

本课采用两类标记。一篇文档含有回答问题所需的明确依据，标为相关；没有这样的依据，标为不相关。只出现相同词语，或只在谈相近主题，都不足以自动标为相关。一个问题需要两篇资料时，可以把两篇都列为相关，并分别说明它们提供哪一部分依据。

标注应查看整批语料，不能只在某个检索器已经返回的前几篇中挑选，否则真正漏掉的文档可能根本没进入标注。50～100 篇短文档的安排，也是在控制这项人工检查的工作量。

一条标注至少包含问题编号、原问题、相关文档编号和简短依据。下面是格式示意，编号需要替换为实际语料中的值。

```json
{
  "query_id": "q01",
  "text": "请求超时后应该怎样限制重试？",
  "relevant_doc_ids": ["超时.md"],
  "reasons": {
    "超时.md": "正文明确要求有限重试。"
  }
}
```

冻结评测材料，是指给这批文档、问题和标注保存一个明确版本，在同一轮比较中不改变它们。若检查后确实需要改标注，记录原因，再让两种方法都重新评测同一个版本。

## 2. Recall@K 看找回了多少

设某个问题的相关文档集合为 R，前 K 个返回位置中命中的相关文档数为 H。

```text
Recall@K = H / 相关文档总数
Precision@K = H / K
```

Recall 常译为召回率，问的是已有相关文档中找回了多少。Precision 常译为精确率，问的是前 K 个位置中有多少是相关结果。

本课的 Precision@K 固定用 K 作分母，返回不足 K 篇时，空缺位置按未命中处理。它与“相关结果数除以实际返回数”的集合精确率分开。比如 K 为 3，只返回一篇且相关，本课的 Precision@3 为 1/3。

本课采用“相关文档中找回的比例”作为 Recall@K。有些资料把“前 K 篇至少命中一篇”也称为 Recall@K，那实际是在回答另一个问题。对照工具时先核对定义。[ir-measures 的指标说明](https://ir-measur.es/en/latest/measures.html#r)区分了 Recall 与 Success。

### 用一份固定排名算三遍

下面的 A～E 是教学文档编号，相关集合为 `{B, D}`，完整排名为 `[A, B, C, D, E]`。

| K   | 前 K 个位置   | H   | Recall@K | Precision@K |
| --- | ------------- | --- | -------- | ----------- |
| 1   | A             | 0   | 0        | 0           |
| 3   | A、B、C       | 1   | 1/2      | 1/3         |
| 5   | A、B、C、D、E | 2   | 1        | 2/5         |

增大 K 会保留原有前缀并加入后面的结果，因此对固定排名，Recall@K 不会下降。Precision@K 可能升高，也可能下降。K 大了会让后续生成模型看到更多资料，同时增加输入长度与无关内容，第一阶段学过的上下文预算会在这里重新派上用场。

## 3. RR 与 MRR 看第一篇相关文档排在哪里

Reciprocal Rank 简写为 RR，中文常称倒数排名。对一个问题，找到第一篇相关文档的位置 r，得分就是 `1/r`。位置从 1 开始数。

本课只看前 K 个位置，所以记为 RR@K。前 K 个位置没有相关文档，得分为 0。对一批有答案问题的 RR@K 取算术平均，得到 MRR@K，M 表示 Mean，也就是平均。

```text
RR@K = 1 / 第一个相关文档的位置
前 K 个位置未命中时，RR@K = 0

MRR@K = 各有答案问题的 RR@K 之和 / 有答案问题数
```

刚才的 `[A, B, C, D, E]` 在 K 为 3 时，第一篇相关文档 B 位于第 2，RR@3 为 1/2。把 D 从第 4 移到第 3，Recall@3 提高了，RR@3 仍为 1/2。MRR 因而不能替代召回率，它没有告诉你第一篇相关文档之后还找回了多少。

不同工具可能计算完整排名的 MRR，也可能指定截断位置。报告必须写清 K，不能把只拿到前五篇算出的 MRR 当成完整排名的 MRR。[ir-measures 对 RR 的说明](https://ir-measur.es/en/latest/measures.html#rr)也允许声明截断位置。

## 4. 无答案与运行失败分开处理

如果整批语料都没有回答问题的依据，相关集合为空。Recall 的分母为零，第一篇相关文档也不存在。

本课把这类问题单独报告，Recall 与 RR 标记为不适用。Precision 仍可按公式算为 0，但三项都不混入有答案问题的均值。这是本课程的报告约定，用来区分“找已有证据”与“判断资料没有答案”。采用其他评测约定时，应先明确分母与纳入问题的范围。

对于无答案问题，保留原问题、空的相关集合、返回的文档与分数，说明检索器有没有返回内容即可。第三课的向量检索没有无答案检测，高分返回也不能据此判定它已经找到了依据。本课不要求新增拒答或阈值模块。

运行失败则是程序未正常完成，例如模型编码报错或输入维度不符。这类记录应有失败原因和计数，不能伪装成正常的零命中结果。出现技术失败时，将本轮比较标为不完整，修正问题后重跑固定材料，不挑选成功样本替换失败样本。

## 5. 让两种方法用同一把尺子

两种方法使用相同文档、标题正文、查询和人工标注，统一取 K 为 1、3、5。各题先计算指标，再对有答案问题逐题取平均。这个平均办法让每个问题占同样权重，不把命中总数直接除以全部相关文档数。

查询耗时从进入单次查询处理开始，到结果可交给调用方时结束。向量方法包含本题的问题编码、相似度计算和原文回查；关键词方法包含切分、匹配与结果回查。使用单调时钟，例如 Python 的 `time.perf_counter()`。

语料读取、模型加载和整批文档向量生成的耗时另记为准备时间，不能一边计入、一边排除。若第一次查询包含额外初始化，也如实说明。20 个问题只支持小规模实验观察，不足以声称已经测出了稳定的线上延迟分布。

报告至少保留以下信息。

| 记录           | 需要能回答的问题                                       |
| -------------- | ------------------------------------------------------ |
| 材料版本与数量 | 这次用了哪些文档、问题和标注？                         |
| 模型与检索设置 | 向量来自哪里，关键词怎样切分，K 取多少？               |
| 逐问题结果     | 返回哪些编号、分数与耗时，命中哪些人工标注？           |
| 汇总与样本数   | 有答案、无答案和运行失败各有多少题，平均值包含哪些题？ |
| 原文核对       | 差异来自词语匹配、模型排序，还是文档或标注本身？       |

不要把关键词的匹配数与余弦分数直接比较大小。可以比较的是相同问题下的命中、排名，以及按同一口径计算的耗时。

## 6. 交互观察

打开[排名与指标实验](../../projects/retrieval-usage-lab/index.html#metrics)。固定相关文档为第二、第四份资料，使用上移和下移按钮改变顺序。

1. 先把 K 设为 3，记录页面的三个指标，再手算一次。
2. 把一篇相关文档从前三篇以外移到第 3，第一篇相关文档的位置保持不变，观察 Recall 与 RR 的区别。
3. 切换到资料无答案的情形，检查哪些值仍能计算，哪些需要标为不适用。

页面中的相关标记已经由教学样例指定，程序没有自动判断文档相关性。你自己的实验仍须人工检查原文。

## 7. 练习与验收

### 任务 1　准备 20 个问题与人工标注

**目标。** 在看比较结论之前，先保存“什么结果算相关”的依据。

使用已有的 50～100 篇语料，编写 20 个固定问题。覆盖常见表述、意思接近但用词不同的表述、精确标识符，以及资料无答案的情形。对每个问题检查语料，保存相关编号和对应依据。无答案问题的相关集合明确为空，并说明缺少哪种资料。

通过条件如下。

- 每个问题有唯一编号、原问题和明确标注，引用的文档编号实际存在。
- 相关判断按本课的依据标准进行，不能只因为主题相似就标为相关。
- 固定保存问题、语料与标注版本。标注不取自关键词排名或向量排名本身，不能因为某种方法漏检就删掉问题。

### 任务 2　从检索入口运行对比评测

**目标。** 把已有的两种检索接到批量评测中，输出可逐题复查的指标和观察结论。

新增评测入口，读取任务 1 的问题与标注，通过单次检索共用的处理流程执行两种方法。准备步骤可以提前完成一次，但查询编码、方法选择、排序与回查都由应用完成。评测程序计算本课指标，并保存逐题结果与汇总。

通过条件如下。

- 默认离线测试用固定小排名验证命中数、少于 K 篇时的 Precision 分母、第一相关位置、未命中、无答案约定和逐题平均；重复文档编号、未知文档编号或缺失标注明确报错，不能重复算命中。
- 有从评测入口驱动的流程测试，实际走到两种查询处理。测试替身只控制模型向量，不替应用补做排序或指标计算。
- 用真实 Embedding 生成的文档与问题向量完成 20 题比较，报告 K 为 1、3、5 的结果。预设向量的离线通过结果不冒充这份真实实验。
- 保留全部逐题结果、两类时间、适用问题数与失败计数。没有技术失败时完整报告；发生失败时明确标记比较不完整。
- 选至少三个例子查看原文与标注，说明排名为何值得关注。可以分析两种方法都找对、都漏检，或无答案却返回高分的情况，不要求人为制造某种方法更好的结论。

### 知识检查

用本课 A～E 的例子分别说明 Recall@3、Precision@3 和 RR@3。再说明为什么无答案问题、检索漏掉已有依据、编码运行失败应在报告里分开记录。
