# 结构化输出

当模型结果要交给程序继续处理时，输出必须从“看起来像 JSON”升级为明确的数据契约。Schema 约束字段、类型和层级；应用再检查取值范围、跨字段关系、权限和事实依据。

## 1. 三层正确性

| 层次     | 示例失败                         | 负责机制                     |
| -------- | -------------------------------- | ---------------------------- |
| 语法正确 | 缺引号、JSON 被截断              | JSON 解析器                  |
| 结构正确 | 缺 `title`、`questions` 不是数组 | JSON Schema 或类型模型       |
| 业务正确 | 题目为空、引用不存在、日期已过期 | 应用规则、数据库和进一步验证 |

合法 JSON 不代表字段齐全，Schema 通过也不代表内容真实。比如 `{"age": -500}` 可以同时是合法 JSON 和合法整数，但通常不符合业务规则。

## 2. 设计小而严格的 Schema

学习卡片可以定义为：

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["title", "summary", "questions"],
  "properties": {
    "title": { "type": "string", "minLength": 1 },
    "summary": { "type": "string", "minLength": 1 },
    "questions": {
      "type": "array",
      "minItems": 2,
      "maxItems": 5,
      "items": { "type": "string", "minLength": 1 }
    }
  }
}
```

字段名应稳定、有业务含义；枚举只包含应用真正支持的值；默认拒绝未知字段可以尽早发现模型或版本偏差。不要为了避免失败把所有字段都设成可选字符串。

## 3. 原生结构约束与提示生成 JSON

如果模型服务支持基于 Schema 的结构化输出，应优先使用。它通常比只在 Prompt 中写“返回 JSON”更能约束形状，但仍需应用验证：

- 服务支持的 Schema 子集可能有限。
- 安全拒绝、输出截断或网络中断可能没有目标对象。
- 字段内容仍可能违反业务规则或缺乏事实依据。
- SDK 升级后解析类型和错误类型可能变化。

如果服务只支持普通文本，则先解析，再验证；解析失败属于明确失败，不应使用正则表达式从任意 prose 中捞取大括号。

## 4. 失败与修复策略

可选流程：

1. 原始生成只执行一次。
2. 解析和 Schema 验证。
3. 业务规则验证。
4. 根据失败类型选择直接拒绝或进行最多一次修复请求。
5. 修复仍失败时返回可诊断错误。

修复请求会增加成本，并可能改变原意。不能无限递归“让模型修复自己的输出”，也不能自动修复权限字段、金额或写操作参数等高风险内容。

## 5. 结构演进

Schema 是调用方与下游之间的协议。新增必填字段、重命名枚举或改变类型都可能破坏消费者。为 Schema 记录版本，并用固定样本测试旧数据和新数据的兼容性。

业务代码应消费已验证的项目类型，不要在各处直接访问任意字典。这样缺字段会在边界处失败，而不是运行到很远的位置才出现异常。

## 6. 练习与验收

### 任务 1：定义学习卡片 Schema（必须）

基于本课示例增加 `source_ids` 字段，每个来源 ID 必须是非空字符串，数组至少一个元素且不能重复。明确是否允许额外字段。

通过条件：Schema 能拒绝缺字段、空标题、问题数量不足、错误字段类型和额外字段；来源去重若无法由 Schema 表达，则由业务校验完成。

### 任务 2：建立验证流水线（必须）

实现“解析 → Schema → 业务规则 → 项目类型”的边界，分别返回可区分的错误类别。错误日志只记录类别、字段路径和请求 ID，不记录完整模型输出。

通过条件：测试覆盖合法对象、坏 JSON、缺字段、错误类型、无效来源和被截断响应；只有全部验证通过的对象进入业务层。

### 任务 3：实现有限修复（必须）

只允许对低风险的格式失败进行最多一次修复。用 fake 客户端模拟首次失败后成功，以及两次都失败。

通过条件：首次合法时不调用修复；修复成功时总调用两次；再次失败时停止；认证、权限或工具参数失败不会进入格式修复。

### 知识检查（必须）

分别举例说明语法、结构和业务正确性；解释原生 Schema 约束为何仍不能保证事实正确；说明无限修复循环的风险。
