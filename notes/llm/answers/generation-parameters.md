# 生成参数与采样练习回答

本文记录[生成参数与采样](../generation-parameters.md)课程任务 1 的真实模型单变量实验、逐条评判和结论。正式实验的原始请求与响应保存在 [16384-Token temperature 实验 JSONL](../../../projects/llm-terminal-assistant/sampling-results/temperature-16384.jsonl)中；较早的 [512-Token](../../../projects/llm-terminal-assistant/sampling-results/temperature.jsonl)和 [1024-Token](../../../projects/llm-terminal-assistant/sampling-results/temperature-1024.jsonl)实验只用于发现输出预算风险，不纳入以下正式统计。可重复执行的入口、固定输入和命令保存在 [LLM Terminal Assistant 项目](../../../projects/llm-terminal-assistant/README.md#单变量采样实验)中。

## 任务 1：单变量对照

### 实验设置

项目通过 OpenAI Responses API 兼容适配器调用 `deepseek-v4-flash`，把 `temperature` 作为唯一变化的采样参数。三个值分别为 0.2、0.8 和 1.4；OpenAI Responses API 兼容请求的 `top_p` 选项在全部请求中均省略，因此由目标服务采用同一默认行为。

| 设置项       | 固定值                                               |
| ------------ | ---------------------------------------------------- |
| 输入         | 10 个固定且彼此独立的中文标题生成任务                |
| 重复次数     | 2                                                    |
| 总请求数     | 60                                                   |
| 模型         | `deepseek-v4-flash`                                  |
| system 消息  | `You are a helpful assistant.`                       |
| 推理强度     | OpenAI Responses API 的 `reasoning.effort`：`high`   |
| 输出上限     | OpenAI Responses API 的 `max_output_tokens`：16384   |
| 固定采样选项 | OpenAI Responses API 的 `top_p`：省略                |
| 实验采样选项 | OpenAI Responses API 的 `temperature`：0.2、0.8、1.4 |

每次请求只包含同一条 system 消息和当前输入，不携带其他实验请求的历史。每个 temperature 值在两遍运行中都覆盖相同的 10 个输入。正式实验 ID 为 `e55df51e-8373-4657-a708-f755ba4cf2ec`，请求时间为 2026-08-26 12:44:11 至 12:46:05 UTC。60 条请求全部正常完成并产生可见正文。

### 评判方法

逐条评判只检查当前 Prompt 能够支持的内容，不假设尚未提供的文章正文包含某个数字、技巧或效果承诺：

- **通过**：产生 5 个可辨认标题，主题正确，并满足该输入明确要求的清晰度、语气或表达边界。
- **部分通过**：主体任务完成，但至少一个标题包含无依据的数字或效果承诺、表达略显故弄玄虚，或者附加了超出给定信息的解释。
- **失败**：没有得到可评判的完整正文，或者没有完成 5 个标题的基本任务。

原始 JSONL 中的 `judgement` 是实验入口预留的占位对象，真实调用时均保持 `pending`。为了保留原始实验文件，以下表格以 `request_number` 关联原始记录，并保存本次人工评判结果。

### 结论

**质量。** 三组 60 条请求都完成了 5 个标题的主体任务，没有空正文或结构失败。在本次评判规则下，temperature 1.4 组有 13 条直接通过，0.8 组有 12 条，0.2 组有 10 条。部分通过主要来自输入没有依据的时间、比例、效果承诺或过度绝对的措辞。三组差距有限，而且前两次预算探索得到过不同的相对排序，因此不能把本批结果推广为“较高 temperature 普遍提高质量”，也不能把 temperature 当作事实正确度旋钮。

**稳定性。** 相同设置和输入的两遍结果只有一个标题逐字重复，出现在 temperature 0.8 的 `title-02`。完整输出的平均字符相似度分别为 0.441、0.454 和 0.308；1.4 组的表面措辞变化明显更大，0.2 与 0.8 则接近。三组请求全部正常结束，说明 16384 的统一输出预算覆盖了本批次观察到的推理波动，但不能据此保证未来请求永不截断。

**多样性。** 两遍输出的字符相似度显示 1.4 组跨运行变化最大；单次回答内标题相似度也从 0.265、0.261 小幅下降到 0.254。两个指标在本批次方向一致，支持较高 temperature 带来更多表面措辞变化，但差异主要反映文字形式，不代表内容更准确或更有用。

**当前选择。** 对这组标题头脑风暴任务，1.4 在本批次取得最多直接通过结果和最大的跨运行措辞变化，可以作为偏重新颖表达的候选起点；如果更重视保守措辞，可以从 0.8 开始。无论选择哪一组，都应筛除无依据数字、绝对化承诺和输入未提供的产品能力，并持续检查结束状态和正文完整性。

### 输出预算与验收结论

512 和 1024 的预算探索各出现一次 reasoning tokens 耗尽全部输出预算、没有可见正文的情况。把正式实验的统一输出上限提高到 16384 后，60 条请求全部正常结束；本批实际单条最大 usage 输出 Token 为 345，说明这个上限提供了充足余量，但不能由本次样本推导出所有请求所需的最小安全值。

正式实验满足任务 1 的数量与对照要求：三组配置之间只改变 temperature，每组都对相同的 10 个输入执行两遍，共得到 60 条完整输出；逐条评判和质量、稳定性、多样性结论均已记录。任务 1 可以通过验收。

## 任务 3：参数决策记录

以下两组设置都是等待固定样本评测的实验起点，不是脱离任务、模型和接口后仍然成立的最佳配置。为了能够判断结果变化来自哪个参数，首轮只显式选择 temperature，OpenAI Responses API 兼容接口的 `top_p` 选项继续省略并采用目标服务的默认行为，不同时调节 temperature 和 top-p。若后续需要考察 top-p，则固定 temperature，单独进行一轮单变量对照。

### 资料摘要

**目标。** 摘要应忠于给定资料、覆盖关键事实，并在多次运行中保持相对稳定的内容和结构。相比措辞新颖，首轮实验更重视事实一致性、重点覆盖和完整结束。

**参数起点。** 延续任务 1 使用的模型和 OpenAI Responses API 兼容接口，把 temperature 设为 0.2，省略 `top_p`，并暂时把该接口的 `max_output_tokens` 设为 16384。较低 temperature 是减少采样波动的实验起点，不代表事实准确性更高。16384 来自任务 1 对当前模型的预算探索：512 和 1024 都曾被 reasoning tokens 耗尽，而 16384 覆盖了正式实验观察到的用量；它只是为当前模型保留生成空间，不是要求摘要使用完这些 Token，也不是已经验证的最小安全值。

**主要风险。** 较低随机性可能让模型稳定地重复同一个事实错误，也可能使表达过于固定。过大的输出上限会放宽潜在延迟和成本边界，过小则可能导致摘要截断。即使输出措辞稳定，也不能据此判断摘要忠于原文。

**评测方法。** 准备包含不同长度和主题的固定资料，为每份资料预先列出必须覆盖的关键事实和禁止引入的外部信息。对同一输入至少重复运行两遍，逐项检查事实是否能在原文中找到依据、关键事实是否覆盖、是否出现无依据内容、结束原因是否正常，以及多次运行的结构和内容是否稳定。如果任务要求固定字段或 JSON 等结构化输出，还要使用对应的 Schema（模式）验证结果，不能用低 temperature 代替结构验证。

**重新调整条件。** 如果多次运行的内容波动影响使用，并且资料、Prompt 与验证规则已经明确，则在确认目标接口支持的范围后，保持其他设置不变继续降低 temperature，或固定 temperature 后单独测试较低 top-p。如果摘要稳定但事实错误或遗漏，应先修正资料、Prompt、事实核验和 Schema，而不是继续降低随机性。如果结束原因显示达到输出上限，则提高输出预算或缩小、拆分摘要任务；收集足够 usage 数据后，还应尝试把 16384 缩小到能覆盖目标样本的合理值。

### 标题头脑风暴

**目标。** 每个输入应产生多个主题相关、彼此有明显差异的标题，同时避免无依据数字、效果承诺和输入未提供的产品能力。与资料摘要相比，本任务愿意接受更大的措辞波动来换取候选多样性。

**参数起点。** 延续任务 1 的模型和接口，把 temperature 设为 1.4，省略 `top_p`，并暂时把 OpenAI Responses API 兼容接口的 `max_output_tokens` 设为 16384。temperature 1.4 组在现有固定样本中取得了最低的跨运行字符相似度、最低的单次回答内标题相似度和最多的直接通过结果，因此可以作为偏重新颖表达的起点。该结论只适用于本次样本，不说明较高 temperature 普遍提高质量。

**主要风险。** 提高随机性可能增加跑题、夸张表达、无依据数字和虚构能力。temperature 与 top-p 同时提高还会让变化来源难以判断，因此首轮不这样设置。较大的输出上限同样会放宽延迟和成本边界，且不能保证一定产生更好的标题。

**评测方法。** 对固定输入重复生成标题，记录任务 1 已使用的直接通过、部分通过和失败评判，同时比较同一次回答内及多次运行间的标题相似度。人工检查所有标题是否围绕输入主题，是否包含无依据事实或承诺，并检查结束原因与正文完整性。多样性指标只衡量候选差异，不能替代质量和事实检查。

**重新调整条件。** 如果候选仍然过于相似，则在确认目标接口支持的范围后，保持其他设置不变测试更高 temperature，或固定 temperature 后单独测试更大的 top-p。如果跑题、无依据承诺或不合格标题明显增加，则优先回退到现有实验中更保守的 temperature 0.8，并加强 Prompt 约束和结果筛选。如果达到输出上限，则调整预算或减少单次候选数量；收集足够 usage 数据后，也应缩小当前保守预留的输出预算。

### 参数能力边界

生成参数只能改变候选分布、候选集合或生成长度，不能为模型补充资料中不存在的事实，也不能验证事实。较低 temperature 可能提高输出稳定性，但不等于提高准确性；较高 temperature 可能增加表达差异，但不等于提高创意质量。当任务要求固定结构时，应用仍需使用相应的 Schema 验证输出，并对不合格结果进行拒绝或重试。

## 知识检查

### temperature 与 top-p 有什么区别

temperature 调整整组候选 Token 的概率分布形状。较低 temperature 会放大高分候选与其他候选的差距，使概率更集中；较高 temperature 会让分布更平缓，使原本概率较低的候选更有机会被选中。

top-p 是核采样使用的累计概率门槛。模型先按概率从高到低排列候选，再保留累计概率达到该门槛所需的最小候选集合，最后只在这个集合中采样。它控制的是随当前概率分布变化的候选范围，不是固定保留多少个候选。

两者都会影响随机性，但作用位置不同：temperature 先改变概率分布的形状，top-p 再根据累计概率限制候选集合。为了判断某项改动的效果，初次实验应固定一个，只调整另一个。

### 输出上限与上下文窗口是什么关系

上下文窗口限制一次调用中能够容纳的输入 Token 和输出 Token 总量。应用在发送请求前，需要根据最终输入占用的空间，为本轮输出预留预算；输入加上预留输出不能超过所选模型和接口允许的上下文窗口。

输出上限只规定本次调用最多允许生成多少 Token，不会扩大上下文窗口，也不表示模型一定会使用完整预算。模型可以正常提前结束；如果生成达到输出上限才停止，应用则应根据响应的结束原因把结果识别为可能不完整，而不能根据文本是否为空或是否以句号结尾猜测。

### 为什么相同参数仍不一定逐字复现

一次生成由连续多次 Token 选择组成。只要中间某一步采样到了不同候选，后续概率分布和文本就可能逐渐分叉。相同 Prompt、模型和生成参数只规定相同的生成条件，不等于固定每一步的随机选择。

此外，未固定的随机源、服务端模型或推理实现更新、硬件并行计算差异等因素也可能影响结果。因此，需要稳定行为的任务应通过固定样本重复评测、输出验证和业务规则控制风险，不能把参数相同当作逐字复现保证。
